## Для власника

**Мета.** Процес, який виріс у warsaw-beer-bot (спека як контракт, проба перед класифікацією,
храповик, «заявка → доказ», рецензент ≠ автор), стає набором, який ставиться в будь-який
проєкт однією командою й працює однаково в Claude Code і Codex, а в Antigravity — після
пілотних проб. Нічого пивного в ядро не йде.

**Що зміниться для тебе.**
- Для нового проєкту: одна команда `npx detent install` кладе скіли в `.claude/skills/` і
  `.agents/skills/` та блок правил у `CLAUDE.md`/`AGENTS.md`. Блок оновлюється тією ж командою
  між маркерами; твій текст поза маркерами інсталятор не чіпає ніколи.
- Cross-review запускається як `npx detent cross-review` замість `npm run cross-review`. Якщо
  ти не скажеш, хто автор, інструмент відмовиться працювати: вгадати автора з оточення
  неможливо (виміряно у warsaw, §Засновки).
- **Antigravity у реліз 1 входить лише як «експериментальний» рецензент.** Жодну з двох проб
  щодо `agy` не вдалося провести: CLI не встановлено ні у Windows, ні у WSL (є тільки десктопний
  Antigravity 44.5.1, без `agy`). Ставити його я не став без тебе: установка — це запуск
  віддаленого скрипта. Поки проби не пройдуть, `agy` за замовчуванням не обирається.
  **Межа доступу:** у `agy` немає режиму «лише читання». Якщо ти явно запустиш
  `--reviewer agy`, рецензент працюватиме з правами твого користувача: знімок-worktree береже
  лише твій checkout від випадкових правок, а не решту файлів. Пом'якшення — `--sandbox` і
  відсутність автоматичних дозволів, але жодне з них не перевірене пробою.
- **Конституція велить агентові відкривати PR без питання** (override
  `finishing-a-development-branch`, як у warsaw). Це зовнішня дія без підтвердження в кожному
  проєкті, куди ставиться detent. Мерджить і далі лише людина.
- **Збій рецензента не блокує.** Таймаут, помилка запуску чи звіт без рядка результату дають
  маркер `failed (<причина>)`, і PR відкривається або спека йде тобі без перехресного рев'ю.
  У проєкті без CI й без рев'ю на GitHub це означає, що другої пари очей не буде зовсім: маркер
  `failed` — сигнал тобі перезапустити рев'ю руками.
- **Незворотне: публікація npm-пакета `detent`.** Ім'я на npm займається першим `npm publish`
  і назад не відпускається легко; публікує лише власник (див. питання 3).
- warsaw-beer-bot у реліз 1 **не мігрує**: його `scripts/cross-review/` живе далі, перехід —
  окремою зміною в тому репо.
- **Попутна знахідка для warsaw:** його override «шлях `bounded` не застосовується» вже нічого
  не ловить. У Superpowers 7.0.1 гілки `bounded` немає, натомість є «quick, clear task — просто
  зроби» (П-Г). detent формулює override через поведінку; warsaw варто поправити окремо.

**На чому стоїть рішення.**
1. Тип рецензента передається явно; автора з оточення не визначити: `codex exec`, запущений із
   Claude Code, успадковує всі `CLAUDE*` змінні, і навпаки. `[проба]` (warsaw, 2026-09-29;
   перевірки тут не повторював)
2. `codex exec -s read-only` справді не дає писати: спроба запису дала `Read-only file system`,
   файл не з'явився. `[проба]` (П-В1)
3. `codex exec`, якщо stdin не закритий, читає його як додатковий ввід і з'їдає все, що йде
   після нього. Тому раннер завжди закриває stdin. `[проба]` (П-В0)
4. Codex 0.166 у режимі `exec` бачить скіл із `.agents/skills/` навіть у недовіреному
   репозиторії: `detent-probe` стоїть у його списку скілів поруч із вбудованими. `[проба]` (П-В2)
5. `agy -p` підхоплює скіли з `.agents/skills/` у headless-режимі — **не перевірено**. Документація
   третіх сторін каже «так», але офіційної немає, а живої проби не було. Не заявка. `[проба не
   проведена]` (П-А)
6. Gemini 4 Argon доступна тобі в Antigravity CLI — **не перевірено**. За публічними звітами вона
   залежить від тарифу (Ultra або Pro, джерела суперечать одне одному) і від версії CLI (≥ 1.4.3,
   на 1.3.x модель «не розпізнається»). Запасна дорога — `agy` з `modelProvider: gemini` і
   `GEMINI_API_KEY`, теж не перевірена. Не заявка. `[проба не проведена]` (П-Б)
7. У `agy` немає режиму read-only, лише `--sandbox` (обмеження терміналу) і запит дозволу на
   запис у headless. Тому read-only для нього **не гарантований**. Знімок-worktree лише
   відводить випадкові правки від checkout автора, а від запису деінде береже тільки
   `--sandbox` і відсутність `--dangerously-skip-permissions`. `[виведення]` з документації, не
   з проби.
8. Імена скілів у локальній установці — `detent-design-spec` (через дефіс), бо і Claude Code, і
   Codex дозволяють у `name` лише малі літери, цифри й дефіс. `detent:design-spec` (через
   двокрапку) — це простір імен плагіна Claude, і він буває лише в установці плагіном.
   `[виведення]` з документації
9. Superpowers не правиться: override оголошуються в конституції проєкту. `[вимога власника]`
   Але override warsaw застаріли: у Superpowers 7.0.1 `brainstorming` уже не має гілки
   `bounded`, натомість є «quick, clear task — do it», «short doc» для малої зміни й відмова від
   питань. `finishing-a-development-branch` і далі пропонує 3 варіанти, а
   `subagent-driven-development` і далі диспатчить кожну задачу. `[проба]` (П-Г)
10. Скіли вмикаються на точках процесу (пишеться спека, пишеться план, перед PR), а не на
    «почни фічу». `[вимога власника]`
11. Реліз 2 (`ai-pr-review` як GitHub Action) — окрема спека; абстракція рецензента мусить його
    витримати. `[вимога власника]`

**Ключові рішення.**
1. **Одне джерело скілів — тека `skills/` у репо detent; плагін Claude і інсталятор читають її ж.**
   Відкинуто: окремі копії для Claude і для `.agents/` — вони розійдуться за перший місяць.
2. **Інсталятор копіює, а не робить симлінки, і веде маніфест із хешами.** Скіл, який ти змінив
   руками, при оновленні не перезаписується: інсталятор зупиняється й називає його. У
   `CLAUDE.md`/`AGENTS.md` хешується лише блок між маркерами, тож твій текст поза ними оновленню
   не заважає. Відкинуто:
   симлінки — на Windows вони потребують режиму розробника або адміна, а git їх зберігає погано.
3. **Рецензент описується адаптером: як запустити, звідки брати звіт, як розпізнати збій, чим
   гарантується read-only і яка родина моделей.** Правило «рецензент ≠ автор» порівнює
   **родину моделі**, а не назву CLI: Antigravity вміє запускати й Claude, і такий рецензент
   для спеки, написаної Claude, — це той самий автор. Відкинуто: порівнювати назви CLI.
4. **Транспорт рецензента (CLI-процес) відділено від протоколу (промпт, рядок результату,
   маркер).** Реліз 2 додасть HTTP-транспорт до того ж протоколу. Відкинуто: узагальнювати під
   API вже зараз, бо реліз 2 ще не спроєктовано.
5. **`dev-cycle` — для проєктів без Superpowers і вмикається тільки явно**: викликом
   `/detent-dev-cycle` або рядком конституції, який інсталятор додає лише проєкту без
   Superpowers. Сам скіл без виклику не вмикається ніколи. Із Superpowers detent-скіли
   вбудовуються в його кроки. Відкинуто: автоматичний тригер на «почни фічу» — він
   конкурував би з `superpowers:brainstorming`.
- Розглянуто стандартне: **симлінки або git submodule для скілів** — відкинуто, бо Windows
  (рішення 2) і бо submodule тягне чуже репо в історію проєкту.
- Розглянуто стандартне: **`/plugin` Claude Code як єдиний спосіб установки** — відкинуто, бо
  він не дає нічого Codex і Antigravity. Плагін лишається другим шляхом для Claude.
- Розглянуто стандартне: **рецензенти через API замість CLI** — відкинуто для релізу 1: через
  API рецензент не відкриває файли репо сам, треба збирати контекст. Це робота релізу 2.

**Що стане гірше.**
- Ще одна залежність, яку треба оновлювати: правило змінюється в detent, а в проєкт приходить
  лише після `npx detent install`. Між цими моментами проєкт живе на старому тексті.
- Конституція стає спільною для всіх проєктів, тож уточнення під один проєкт мусять іти поза
  маркерами, а не правкою блоку. Інакше наступне оновлення спиниться на зміненому файлі.
- Antigravity у релізі 1 непідтверджений. Якщо проби провалиться, адаптер `agy` лишиться

- Скіли англійською (якщо ти це затвердиш) читатимуться трохи інакше, ніж звичні українські
  правила warsaw. Ризик — розбіжність формулювань між detent і warsaw, поки той не мігрує.
- Рецензент Codex теж бачить усі detent-скіли проєкту (П-В2). Промпт рев'ю самодостатній, але

## Межі релізу

Входить: шаблон конституції, скіли `design-spec`, `pr-slicing`, `cross-review`, `dev-cycle`,
CLI `detent` з командами `cross-review` і `install`, плагін Claude, документація установки.

Не входить:
- `ai-pr-review` як reusable GitHub Action (реліз 2, окрема спека);
- проєктна специфіка warsaw-beer-bot: бюджет, `orphan-triage`, `deploy:hold`, міграції
  expand/contract, чейнджлог розширення. Вони можуть з'явитися лише як приклад у
  `examples/`, не в ядрі;
- міграція warsaw-beer-bot на detent;
- автоматичне визначення автора.

## Конфіг проєкту

`detent.json` у корені проєкту. Інсталятор створює його з дефолтами, якщо файлу немає.

```json
{
  "language": "uk",
  "specFile": "spec.md",
  "specsDir": "docs/specs",
  "plansDir": "docs/plans",
  "gate": "npm test && npm run typecheck",
  "baseBranch": "origin/main",
  "tmpDir": "tmp",
  "reviewers": ["codex", "claude", "agy"],
  "models": { "codex": "gpt-6.1-sol", "agy": "gemini-4-argon" }
}
```

- `language` задає мову артефактів: спек, планів, маркерів і секції «Для власника». Скіли
  написані англійською й велять писати артефакти мовою з конфігу (питання 1).
- `reviewers` — порядок вибору, коли `--reviewer` не задано (див. «Вибір рецензента»).
- `models` закріплює модель. Причина — warsaw, 2026-10-01: дефолт CLI рухається з апдейтами.
  Без запису діє дефолт CLI.
- Місячні підтеки (`<specsDir>/<YYYY-MM>/`) — правило конституції, а не конфігу.

## Шаблон конституції

`constitution/constitution.md` вставляється в `CLAUDE.md` і `AGENTS.md` між маркерами:

```
<!-- detent:constitution v1 begin — edit outside these markers; `npx detent install` rewrites this block -->
…
<!-- detent:constitution end -->
```

Зміст (англійською, з посиланнями на шляхи з `detent.json`):

1. **Spec is the single source of truth.** Перед зміною поведінки — прочитати `specFile`; якщо
   зміна потребує нового речення в спеці — оновити її в тому ж PR; коли код і спека
   розходяться, перемагає спека, а розбіжність — дефект коду або привід для зміни спеки
   повним циклом.
2. **Classification after the probe, never on entry.** Три шляхи: `spike` (нічого не комітить),
   легкий шлях, повний цикл. Легкий шлях — лише якщо виконані всі чотири умови: (а) фікс
   відновлює поведінку, яку спека вже описує, без нового речення в ній; (б) механізм дефекту
   доведено живою пробою або реплеєм до класифікації; (в) зміна вміщується у два файли плюс
   їхні тести й не вводить нового поняття; (г) вона не міняє правила, що діє на всі дані.
   Слід легкого шляху — issue плюс коміт, який називає механізм.
3. **One-way ratchet.** Щойно відпала хоч одна умова, робота зупиняється, здобуте
   записується як вхідні дані, і зміна починається повним циклом з початку. Спеку заднім
   числом під готовий фікс не пишуть; донизу не перекласифіковують.
4. **Claim → evidence.** Кожне місце, де система записує щось як факт, дістає рядок у таблиці
   спеки. Формат — у скілі `detent-design-spec` (файл `spec-format.md` лежить у теці скіла й
   ставиться разом із ним), тож конституція посилається на скіл, а не на шлях у проєкті.
5. **Test quality.** Точні асерти, що фіксують власний факт тесту, а глобальне значення, яке
   росте, фіксує рівно один тест; жодної умовної логіки; жодних тавтологій і перевірок стану
   мока замість коду; межі, порожні входи й помилки; очікуване значення не обчислюється
   повторенням логіки продакшну.
6. **The reviewer is not the author.** Спеку й diff перед PR рецензує модель іншої родини,
   через `npx detent cross-review`; протокол — у скілі `cross-review`.
7. **Superpowers overrides** (діють, лише якщо Superpowers встановлено). Override описують
   **поведінку**, а не назви гілок усередині чужого скіла: warsaw писав «шлях `bounded` не
   застосовується», а в Superpowers 7.0.1 гілки `bounded` уже немає (П-Г). Блок несе рядок
   «checked against Superpowers 7.0.1»; новий мажор Superpowers — привід перечитати override.
   - `superpowers:brainstorming`: гілки «quick, clear task — do it» і «small change — short
     doc» не обходять класифікацію. Зміна поведінки без спеки можлива лише легким шляхом
     (чотири умови, після проби); усе інше — повна спека за `detent-design-spec`. Відмова
     людини від питань («opted out») не скасовує спеку, лише питання.
   - `superpowers:writing-plans`: план ріжеться за скілом `detent-pr-slicing`.
   - `superpowers:subagent-driven-development`: дрібна задача робиться інлайн (умови — у
     `detent-pr-slicing`).
   - `superpowers:finishing-a-development-branch`: PR відкривається за замовчуванням, без
     питання; мерджить людина.
8. **Deletion.** Рекурсивне видалення — лише скриптом із літеральними шляхами, показаним
   власнику з dry-run, ніколи інлайн і ніколи у фоні. Це правило з інциденту 2026-10-31, і воно
   не специфічне для warsaw.

Чого в конституції немає: `deploy:hold`, міграцій, бюджету, правил чейнджлогу, триажу сиріт.

## Скіли

Усі скіли — англійською, з frontmatter `name`/`description`. Опис формулює **точку процесу**,
а не намір («Use when writing a design spec…», «Use before opening a PR…»), щоб не
перехоплювати «почни фічу» в `superpowers:brainstorming` (засновок 10).

### `detent-design-spec`

Тригер: пишеться архітектурна спека.

Вміст — перенесений і очищений від warsaw `docs/spec-format.md`:
- заголовок із рядками `Статус:` і `Spec-review:`;
- секція «Для власника» з полями по порядку: Мета, Що зміниться для тебе, На чому стоїть
  рішення (кожен засновок має позначку `[вимога власника]`, `[проба]` або `[виведення]`),
  Ключові рішення з відкинутими альтернативами й рядками «Розглянуто стандартне», Що стане
  гірше, Оцінка, Питання до власника (≤ 3);
- тіло для того, хто пише план;
- таблиця «заявка → доказ»: рядок із лічильником, припущенням про зовнішні дані або «так завжди
  було» в колонці доказу — слабкий, його перевіряють пробою до плану або не пишуть;
- гра в оцінку: переказ задачі й питання оцінки власника, своєї не називаючи; своя — коли
  підхід обрано, з розкладом і дешевшим варіантом; розбіжність ≥ 2 розміри — зупинка й розбір;
  після мерджу останнього PR — «Фактично: <розмір>, <n> PR, <m> задач».

Шкала узагальнюється: у warsaw L означало «2–3 PR **або крок на хості** (`[deploy:hold]`)».
У detent: «L — 2–3 PR або крок, який виконує людина поза репо». Інше без змін:

| Розмір | Що означає |
|---|---|
| XS | без коду або одна правка легким шляхом |
| S | один PR, план ≤ 4 задачі |
| M | один PR, ядро + окремий план на обв'язку |
| L | 2–3 PR або крок, який виконує людина поза репо |
| XL | розпадається на кілька спек |

Поле «Мета» в warsaw прив'язане до «людини, яка питає про пиво, або бюджету». У detent —
«що зміниться для користувача продукту або для ресурсів проєкту».

### `detent-pr-slicing`

Тригер: пишеться план або вирішується, як різати зміну на PR.

- План більший за ~4 задачі або з пізніми задачами на механізмі, якого ще немає: спершу план на
  **ядро**, реалізація, **наскрізне рев'ю**, лише потім окремий план на обв'язку. Спека одна на
  всю зміну.
- Рефакторинг, що супроводжує зміну поведінки, — **двома PR**: спершу like-for-like (поведінка
  та сама, тести ті самі й зелені без правок), потім зміна. Ознака порушення: PR, у якому
  змінюються і структура, і очікування тестів.
- Розмір задачі оцінюється до диспатчу. Дрібна — якщо (а) текст задачі містить повний код,
  (б) зачіпає ≤ 2 файли плюс їхні тести, (в) не вимагає нового рішення. Тоді вона робиться
  інлайн із повним гейтом і комітом, і **обов'язково** входить у пакет рев'ю наступної задачі.
  Інакше — диспатч.

### `detent-cross-review`

Тригер: спека закомічена й чекає власника; або гейт зелений, рібейс зроблено, і PR ось-ось
відкриється.

- Запуск **у фоні**: рев'ю триває до 15 хв, а foreground-команди агентів обриваються раніше
  (у Claude Code — 10 хв).
- Автор передається явно: `--author claude|codex|agy` або змінна `DETENT_AUTHOR`. Скіл у
  кожному агенті підставляє своє значення сам. Claude Code читає скіл із `.claude/skills/`,
  Codex і Antigravity — з `.agents/skills/`, тож інсталятор кладе в кожну теку версію з
  власним рядком «you are <author>» (див. «Установка»).
- Протокол розбору: кожна знахідка або виправлена, або відхилена з причиною; ніколи не
  застосовується наосліп. Маркер — у опис PR (`Cross-review: …`) або в заголовок спеки
  (`Spec-review: …`), таблиця рішень — у розділ `## Рев'ю спеки`.
- Один раз на PR чи спеку. Не після фіксів у відкритому PR і не після поправок до
  затвердженої спеки. PR лише з документами: `Cross-review: skipped (docs-only)`.
- Збій рецензента (exit 5) не блокує: маркер `failed (<причина>)`, і гейтом лишається
  звичайне рев'ю. Скіл велить назвати збій людині в повідомленні, а не лише в маркері: у
  проєкті без рев'ю на GitHub іншої пари очей не буде.

### `detent-dev-cycle`

Тригер: лише явний виклик. Description: «Only when invoked explicitly». Явним вважається і
рядок конституції «Without Superpowers, start any behaviour change with `detent-dev-cycle`»:
інсталятор додає його лише тоді, коли Superpowers у проєкті не видно, і друкує, що додав.
Послідовність:

1. Переказ задачі, оцінка власника (гра з `detent-design-spec`).
2. Проба: відтворити, виміряти, перевірити засновки.
3. Класифікація за конституцією: spike / легкий шлях / повний цикл.
4. Повний цикл: спека (`detent-design-spec`) → `cross-review --spec` → затвердження власника →
   план (`detent-pr-slicing`) → реалізація задача за задачею з гейтом → наскрізне рев'ю ядра →
   план на обв'язку → рібейс, гейт → `cross-review` → PR.
5. Легкий шлях: фікс → гейт → `cross-review` → PR; храповик діє на кожному кроці.

Якщо Superpowers встановлено, `dev-cycle` на першому кроці каже про це й передає керування
`superpowers:brainstorming`: detent-скіли самі вмикаються на своїх точках.

## CLI `detent cross-review`

### Інтерфейс

```
npx detent cross-review --author <id> [--reviewer <id>] [--base <ref> | --spec <file>] [--model <id>]
```

Що успадковується з warsaw без змін (там воно вже пройшло рев'ю й інциденти):
- відмова на брудному дереві й на порожньому diff; `--spec` вимагає, щоб файл був у `HEAD`;
- `--spec` і `--base` разом — помилка використання;
- рецензент працює в **знімку-worktree** точного SHA, у власній теці запуску
  `<tmpDir>/cross-review-[spec-]<reviewer>-<branch>-<sha7>-XXXXXX/`, і знімок прибирається у
  `finally` через `git worktree remove --force` (це не рекурсивне видалення, а команда git
  над її власним worktree);
- таймаут 15 хв, `SIGKILL`; stdin рецензента закритий (засновок 3);
- `CROSS_REVIEW_ACTIVE=1` у середовищі рецензента й відмова на вкладеному запуску (exit 3);
- класифікація результату: таймаут, помилка spawn, ненульовий код з **останнім** непорожнім
  рядком помилки на потоці цього рецензента, відсутній рядок `CROSS-REVIEW-RESULT: <n>
  findings`;
- коди виходу: 0 — ок, 2 — використання, 3 — вкладений запуск, 5 — збій рецензента;
- на виході — рядок маркера із заготовкою `<f> fixed, <r> rejected`.

Що змінюється:
- `--author` обов'язковий (або `DETENT_AUTHOR`); `--reviewer` — необов'язковий.
- Шлях спеки перевіряється проти `specsDir` з конфігу (`<specsDir>/<YYYY-MM>/*.md`), а не проти
  захардкодженого `docs/superpowers/specs/`.
- Промпти беруться з `prompts/` пакета, але проєкт може перекрити їх файлом
  `.detent/prompts/review-{diff,spec}.md`. Плейсхолдери ті самі; невідомий плейсхолдер — помилка.
- Промпти узагальнено: «warsaw-beer-bot» → `{{project}}` (з `package.json` або імені теки);
  обмеження проєкту («one host, SQLite, $20–40/month») прибрано з ядра й перенесено в
  необов'язкове поле конфігу `reviewContext`, яке підставляється в промпт як є.
- Маркер називає й модель: `Cross-review: codex/gpt-6.1-sol @ <sha7> — …`. Це потрібно, щоб
  порівнювати рецензентів між собою (`ai-review-model-evaluation.md`: порівняння без назви
  конфігу нічого не міряє).

### Адаптер рецензента

```ts
interface ReviewerAdapter {
  id: 'claude' | 'codex' | 'agy';
  family: 'anthropic' | 'openai' | 'google';   // для правила «рецензент ≠ автор»
  status: 'stable' | 'experimental';            // experimental не обирається автоматично
  readOnlyBy: 'sandbox' | 'toolset' | 'isolation';
  acceptsModel(model: string): boolean;          // agy: лише gemini-*
  command(p: { model?: string; prompt: string; reportPath: string; runDir: string }): {
    cmd: string; args: string[]; report: 'stdout' | 'file';
  };
  errorLine: { stream: 'stdout' | 'stderr'; prefix: string };
}
```

| id | Команда | Read-only тримає | Статус |
|---|---|---|---|
| `codex` | `codex exec -s read-only --ephemeral -o <report> [-m <model>] <prompt>` | пісочниця Codex (П-В1) | stable |
| `claude` | `claude -p --restricted --strict-mcp-config --tools Read,Grep,Glob --add-dir <runDir> [--model <m>] -- <prompt>` | набір інструментів без запису (warsaw P2) | stable |
| `agy` | `agy -p <prompt> --model <m> --sandbox --output-format text --print-timeout 15m` | не гарантований: `--sandbox` і без `--dangerously-skip-permissions`; знімок лише відводить правки від checkout автора | experimental |

Рядки помилок: `claude` — stdout, `API Error:`; `codex` — stderr, `ERROR:` (П-В3 повторно
підтвердив форму: `ERROR: The 'no-such-model-xyz' model is not supported…`, exit 1). Для `agy`
документація каже лише «non-zero exit, reason on stderr»; префікс невідомий, тож до проби
`agy` класифікується за кодом виходу, без розбору рядка.

Чому `agy` — `experimental`, а не просто ще один рядок: (1) його read-only не гарантується
інструментом, лише ізоляцією, тож рецензент **може** писати у знімок і, якщо пісочниці немає,
поза ним; (2) за документацією `--print-timeout` за замовчуванням 5 хв, тож без явного прапорця
рев'ю обривалося б утричі раніше за власний таймаут раннера; (3) жоден із його прапорців не
перевірено живою пробою. Перехід у `stable` — окремою поправкою до спеки після П-А і П-Б.

### Вибір рецензента

1. Спершу визначається **остаточна модель** рецензента: `--model`, інакше `models.<id>` з
   конфігу, інакше дефолт CLI. Явна модель з будь-якого джерела мусить пройти `acceptsModel`,
   інакше exit 2. Тому `models.agy: "claude-…"` у конфігу відкидається так само, як
   `--model claude-…`. Для `agy` без явної моделі exit 2: дефолт CLI невідомий, і родину
   неможливо довести.
2. Якщо задано `--reviewer`: його адаптер мусить мати `family`, відмінну від родини автора,
   інакше exit 2 з поясненням.
3. Якщо ні: перший у `reviewers` з конфігу, у якого `family` ≠ родина автора, `status` =
   `stable` і бінарник є в `PATH`. Немає такого — exit 2 зі списком причин по кожному.
4. Родина автора виводиться з `--author`: `claude` → anthropic, `codex` → openai, `agy` →
   google. Автор `agy`, що працював на Claude-моделі, мусить передати `--author claude`: правило
   стосується моделі, яка писала, а не CLI, і скіл `cross-review` в `.agents/skills/` каже це
   явно.

### Під реліз 2

Протокол (`renderPrompt`, `classifyResult` без транспортних полів, `markerLine`,
`markerReason`, рядок `CROSS-REVIEW-RESULT`) живе в `src/review/protocol.ts` і нічого не знає
про процеси. Раннер CLI (`src/review/cli-runner.ts`) — єдине місце, де є `spawnSync`, worktree і
таймаут. Реліз 2 додасть HTTP-транспорт поруч. Що саме йому знадобиться (find/verify,
JSON-схема, збірка контексту), реліз 1 не вгадує й інтерфейсу під це не додає.

## Установка

```
npx detent install [--claude] [--agents] [--dry-run]
```

Без прапорців — обидві цілі.

- `--claude`: `skills/<name>/` → `.claude/skills/detent-<name>/`; блок конституції → `CLAUDE.md`.
- `--agents`: `skills/<name>/` → `.agents/skills/detent-<name>/`; блок → `AGENTS.md`.
- Скіл `cross-review` у кожній цілі дістає рядок про автора (`claude` для `.claude/`, для
  `.agents/` — інструкцію передавати `codex` чи `agy` залежно від того, хто запущений, або
  родину моделі, якою працює agy).
- `detent.json` створюється, якщо його немає; існуючий не чіпається.
- `tmpDir` дописується в `.gitignore`, якщо його там немає.
- Маніфест `.detent/manifest.json`: для кожного файлу скіла — шлях, версія detent, sha256
  файлу; для `CLAUDE.md`/`AGENTS.md` — sha256 **лише блоку між маркерами**, бо текст поза ними
  належить проєкту. При повторній установці файл скіла чи блок, чий поточний хеш не
  збігається з маніфестом, **не перезаписується**: інсталятор друкує список і виходить з
  кодом 4, нічого не змінивши (спершу перевіряє все, потім пише). Прапорця «force» немає: змінений файл власник повертає
  руками або переносить зміну поза маркери.
- Інсталятор **ніколи нічого не видаляє**. Скіл, якого в новій версії немає, лишається, а
  інсталятор друкує його шлях як «застарілий, видали скриптом, якщо не потрібен».
- Блок конституції замінюється лише між маркерами. Немає маркерів — блок дописується в кінець
  файлу. Маркер є, але один (обірвана пара) — exit 4, без запису.
- `--dry-run` друкує точний список того, що буде створено чи змінено.

Плагін Claude: `.claude-plugin/plugin.json` посилається на `skills/`, `marketplace.json`
дозволяє `/plugin marketplace add ysilvestrov/detent`. У плагіні скіли називаються
`detent:<name>`. Плагін не кладе конституцію: її ставить `npx detent install --claude`.
Одночасна установка плагіном і копіюванням дасть дублікати (`detent:design-spec` і
`detent-design-spec`). Інсталятор попереджає, якщо бачить плагін увімкненим у
`.claude/settings.json`.

## Заявка → доказ

| Що detent записує як факт | Де | Що це доводить | Сила |
|---|---|---|---|
| «Рев'ю описує саме `<sha>`» | маркер `Cross-review:`/`Spec-review:` | рецензент працював у знімку-worktree цього SHA, створеному до запуску | за конструкцією |

| «Рецензент ≠ автор» | маркер | `--author` — заява того, хто викликає; інструмент перевіряє лише, що родини різні | заява, не доказ; маркер її так і називає (`author: claude`) |
| «n findings: f fixed, r rejected» | маркер | `n` — з рядка `CROSS-REVIEW-RESULT`; `f` і `r` — самозвіт автора | самозвіт, нічого не вмикає; таблиця `## Рев'ю спеки` — слід |
| «Скіл установлено й актуальний» | `.detent/manifest.json` | sha256 записаного файлу на момент запису | доводить лише момент запису; перевірка при кожній установці |
| «Скіл підхоплюється агентом» | README, установка | Codex — так, П-В2; Claude Code — `.claude/skills/` за документацією, тут не перевірено; `agy` — не перевірено (П-А) | README заявляє лише Codex і Claude Code; `agy` — після П-А |
| «Фактично: <розмір>» | спека | кількість PR і задач у планах — лічильник | лічильник, але він і є предметом заявки |

не роблю.

Що каже документація (третіх сторін, не офіційна):
- `-p/--print` — неінтерактивний запуск; `--output-format text|json|stream-json`;
  `--print-timeout` (дефолт `5m`); `--disable-slash-commands` вимикає розгортання скілів у
  print-режимі, тобто за замовчуванням вони, ймовірно, ввімкнені;
- скіли робочого простору: `.agents/skills/<name>.md` або `.agents/skills/<name>/SKILL.md`;
  глобальні — `~/.gemini/antigravity-cli/skills/`; правила — `GEMINI.md`, `AGENTS.md`,
  `.agents/rules/*.md`; чи вантажиться `AGENTS.md` у `-p`, документація не каже;
- інструменти запису й команд у headless за замовчуванням «Ask», тобто м'яко відхиляються.
  Режиму read-only немає, є `--sandbox` (обмеження виконання в терміналі) і `--mode plan`.

Що зробити, коли `agy` буде: у тимчасовому репо зі скілом `detent-probe` (як П-В2)
`agy -p 'What is the detent probe word?…' < /dev/null`, потім спроба запису файлу без
`--dangerously-skip-permissions` і з `--sandbox`/`--mode plan`, потім некоректна модель, щоб
побачити рядок помилки.

### П-Б. Gemini 4 Argon в Antigravity CLI і запасна дорога — **не проведена**

Причина та сама. За публічними звітами (жовтень 2026):
- модель вийшла 2026-10-13, ID в API — `gemini-4-argon`;
- в `agy` 1.3.4–1.3.5 вона не розпізнавалася («model gemini-4-argon is not recognized… Using
  "Gemini 3.8 Flash (High)" instead»), мейнтейнер позначив фікс у 1.4.3. Тобто **CLI тихо
  підмінює модель** — і це дефект для рецензента: маркер назвав би Argon, а рецензував би
  Flash. Наслідок для дизайну: адаптер `agy` мусить перевіряти назву моделі у виводі або
  відмовлятися, якщо підтвердити її неможливо — це вирішить П-Б;
- доступ залежить від тарифу (Ultra; про Pro джерела суперечать) і версії клієнта;
- запасна дорога: `"modelProvider": "gemini"` у `~/.gemini/antigravity-cli/settings.json` +
  `GEMINI_API_KEY`. Ключ платний поза Free tier, а Argon на Free tier, за звітами, недоступна.

Що зробити: `agy --version` (≥ 1.4.3), `agy models` на акаунті власника; `agy -p 'reply PONG'
--model gemini-4-argon` і перевірити, чи є попередження про підміну в stderr; те саме з
`GEMINI_API_KEY`.

### П-В. Codex CLI як read-only рецензент — **проведена**

Тимчасовий git-репо у WSL `/tmp`, файл `note.txt` і скіл `.agents/skills/detent-probe/SKILL.md`.

**П-В0, stdin.** Перший запуск скрипта через `… | wsl -e bash -i -s` обірвався на першому ж
`codex exec`: решта скрипта зникла. У stderr наступних запусків видно `Reading additional input
from stdin...`. Codex читає stdin, якщо той не закритий. Раннер warsaw уже передає
`stdio: ['ignore', …]`; detent зберігає це як вимогу, а не випадковість.

**П-В1, read-only.** `codex exec -s read-only --ephemeral -o <report> '<прочитай note.txt, спробуй
створити written.txt>' < /dev/null`:

```
exit=0
model: gpt-6.1-sol / approval: never / sandbox: read-only
report: `note.txt` contains: > hello from probe
        Ran `printf x > written.txt`. It failed with exit code 1:
        /bin/bash: line 1: written.txt: Read-only file system
-- written.txt exists? no
```

**П-В2, скіли з `.agents/skills/`.** Питання про «detent probe word» з вимогою відповідати зі
списку скілів, а не з файлової системи:

```
exit=0
report2: UNKNOWN
```

Це був артефакт промпту, а не відповідь. Скіли відкриваються поступово: у контексті лише
`name` і `description`, а тіло агент читає з `SKILL.md` — тобто саме з файлової системи, яку я
заборонив. Наступні дві проби в новому тимчасовому репо (у `~/.codex/config.toml` немає жодного
запису про довіру, файла взагалі немає):

```
== C2b: "List, verbatim, the names of all skills available to you…"   (недовірений проєкт)
exit=0
imagegen / openai-docs / skill-creator / skill-installer / detent-probe

== C2e: "What is the detent probe word? Name the skill you used, if any."
exit=0
TURNSTILE-42. Skill used: detent-probe.
exec: /bin/bash -lc 'cat …/superpowers/7.0.1/skills/using-superpowers/SKILL.md
                     /tmp/detent-probe-c3-Xqb03G/.agents/skills/detent-probe/SKILL.md'
```

Висновок: Codex 0.166 у `exec` бачить і застосовує скіли з `.agents/skills/` без жодного
налаштування довіри. Попутно видно, що в Codex власника стоїть плагін Superpowers 7.0.1, і він
вантажить `using-superpowers` навіть у read-only рецензента (див. П-Г).

**П-В3, некоректна модель.**

```
exit=1
ERROR: The 'no-such-model-xyz' model is not supported when using Codex with a ChatGPT account.
```

Форма помилки збігається з тим, що розбирає warsaw (`stderr`, префікс `ERROR:`).

## Ризики й відкриті питання для плану

- `claude` CLI немає в WSL і в Windows PATH цього оточення; рецензента `claude` тут не
  запустиш. План має перевірити, де його встановлено, до порту адаптера.
- Windows: раннер warsaw жив у WSL. detent мусить працювати й у PowerShell: шляхи через
  `node:path`, без `bash -lc`, `spawnSync` без shell. Тест — на обох.
- Ім'я `detent` на npm вільне (за постановкою задачі, не перевірено тут).
