# AI-рев'ю PR у GitHub як частина detent

Дата: 2026-11-02
Статус: чекає на затвердження
Spec-review: codex/gpt-6.1-sol @ 29c5a51 (author: claude) — 7 findings: 7 fixed, 0 rejected

## Для власника

**Мета.** Кожен push у PR будь-якого проєкту з detent автоматично отримує незалежне рев'ю від AI, яке
не залежить від середовища автора. Механізм, що вже працює у warsaw-beer-bot, стає частиною пакета,
а не окремою копією в кожному репозиторії.

**Що зміниться для тебе.**
- Щоб увімкнути рев'ю в проєкті, досить додати секрет `OPENAI_API_KEY` і файл workflow приблизно на
  20 рядків. Далі воно працює без тебе на кожен push.
- Твої дії поза репозиторієм: опублікувати `0.4.0` у npm (випуск лишається ручним) і зливати PR. Без
  публікації Action не запрацює.
- warsaw-beer-bot переходить на пакет: понад 2000 рядків власного коду рев'ю звідти зникають, його
  настройки переїжджають у `detent.json` і `.detent/prompts/`.
- Знахідки лишаються коментарем і нічого не блокують. Червона перевірка злиття теж не блокує, доки ти
  сам не зробиш її обов'язковою в налаштуваннях гілки: ця зміна її обов'язковою не робить.
- Рецензуються не всі PR. Без виклику моделі лишаються PR, де змінено лише документацію (`*.md`, `docs/**`,
  зокрема код у `docs/`) чи `package-lock.json`, PR із форків, бо там немає секретів, і PR від Dependabot. Перелік
  файлів можна змінити в проєкті.
- Перед переходом warsaw-beer-bot я запущу порівняння старої й нової версій: 5 голів PR, по 3 прогони на версію,
  тобто 30 прогонів, орієнтовно до $15 за твоїм ключем. Суму я вивів, а не зміряв. Затвердження спеки означає згоду
  на цю витрату.
- Сам репозиторій detent рев'ю в цій зміні не вмикає: це окремий ключ і витрати, а першим справжнім запуском і так
  стане warsaw-beer-bot. Увімкнути можна будь-коли за інструкцією в README.
- Незворотного немає: перехід warsaw-beer-bot скасовується revert'ом. Опублікована версія npm лишається
  назавжди, але нічого не ламає.

**На чому стоїть рішення.**
1. Рев'ю потрібне понад `cross-review`: на 23 з 51 PR автор виправив знахідки CI в уже переглянутому
   коді (разом 58, у п'яти PR після вердикту «0 знахідок»); у 40% PR `cross-review` не відпрацював;
   CI перевіряє кожен push, зокрема фікси. Ціна близько $0,34 на PR. Це твої дані з warsaw-beer-bot;
   я їх не переміряв. `[вимога власника]`
2. Рев'ю постачається в наборі detent. warsaw-beer-bot на нього переходить. `[вимога власника]`
3. Форма: команда в npm-пакеті плюс тонка GitHub Action, яка її запускає. `[вимога власника]`
4. У CI одна модель із налаштувань, без визначення автора. Правило родин стосується лише
   `cross-review`. `[вимога власника]`
5. Ядро warsaw-beer-bot майже не прив'язане до проєкту: специфіка зібрана в переліках файлів, двох
   промптах і одному заголовку. `[проба]` (П-1)
6. Єдина стороння залежність ядра — `zod`, у трьох файлах. detent обіцяє відсутність залежностей під час
   роботи. `[проба]` (П-1)
7. `npx` із версією всередині самого репозиторію detent не працює, а встановлення в окрему теку
   працює. `[проба]` (П-2)
8. Формат збереженого стану на живих PR лишається читабельним для нової версії, бо переноситься без
   змін. `[проба]` (П-4) для наявності стану, `[виведення]` для сумісності: покаже приймання.
9. Цифри з пункту 1 не переносяться автоматично: вони зміряні на налаштованих промптах одного проєкту. У
   нового проєкту із загальними промптами вони можуть бути іншими. `[виведення]`
10. `actions/checkout` з `fetch-depth: 0` дає `origin/<база>` без збережених облікових даних, і
    цього вистачає для приватного репозиторію. `[виведення]`: перевірить перший запуск.

**Ключові рішення.**
1. **Команда `detent pr-review` і тонка Action, що ставить пакет закріпленої версії в окрему теку.**
   `smoke` перевіряє те саме, що запускає CI, а випуск один. Відкинуто: окрема JS Action зі зібраним
   кодом у git (другий канал постачання, який розійдеться з npm); повний workflow, який копіює `install`
   (кожне виправлення треба розносити по репозиторіях).
2. **Настройки, ендпойнт і промпти читаються з базової гілки, а не з коду PR.** Інакше PR міг би
   непомітно переписати інструкції рецензенту або спрямувати ключ API на чужий ендпойнт. Захист неповний:
   за події `pull_request` сам workflow береться з PR, але така зміна видна в diff. Відкинуто: читати з
   голови PR, як зараз у warsaw-beer-bot.
3. **`zod` замінюємо власними перевірками.** Обіцянка «без залежностей» зберігається. Ціна: близько 40
   рядків перевірок, які треба покрити тестами. Відкинуто: додати `zod` у `dependencies`.
4. **Збій робить перевірку червоною й пише в PR. Без ключа червоно теж, крім PR із форка.** Тихий пропуск
   повторив би проблему `cross-review`. У PR із форка секретів немає за правилами GitHub, тож там лише
   повідомлення в журналі й зелений статус. Відкинуто: зелений статус за будь-якої відсутності ключа.
5. **Ядро переносимо цілком: два етапи, фільтр цитат, пам'ять між push'ами, облік витрат.** Саме на цьому
   стоять цифри з пункту 1. Відкинуто: один прохід і коментар (дешевше, але цифри не гарантує).
6. Розглянуто стандартне: `anthropics/claude-code-action` та подібні готові дії — відкинуто, бо це агент з
   інструментами й правами у робочому дереві, а не текстовий виклик без інструментів, і вони не дають двох
   етапів, фільтра цитат і обліку витрат, на яких стоять цифри.

**Що стане гірше.**
- Близько 2100 рядків коду й 3000 рядків тестів стають підтримкою detent.
- Гроші: ключ API кожного проєкту платить за кожен push із кодом. Простий PR коштує близько $0,34 за твоїми
  даними, складний більше: PR #939 у warsaw-beer-bot дійшов до $1,24 (П-4).
- Таблиця цін у пакеті старіє. Ціна `gpt-5.6-sol` гарантована лише до 2026-11-21, далі рядок витрат може
  занижувати рахунок, а виправлення приїде лише з новою версією пакета. Звірити таблицю перед випуском.
- Порядок випуску стає важливим: Action не запрацює, поки потрібну версію не опубліковано в npm.
- PR, що змінює `prReview` чи промпти, проходить рев'ю за старими настройками: нові діють після злиття.
  Сам PR переходу warsaw-beer-bot отримає одне рев'ю із загальними промптами.
- Рецензент лише текстовий, але вміст PR потрапляє в промпт. Підроблений текст у PR може вплинути на
  знахідки, хоча нічого не може запустити. Це вже так у warsaw-beer-bot.
- PR від Codex без `cross-review` бачить лише OpenAI: незалежної родини там немає. Це свідоме обмеження.
- Новий публічний імпорт `@ysilvestrov/detent/pr-review` для інструментів вимірювань warsaw-beer-bot. Він
  позначений нестабільним, але це вже поверхня, яку легко зламати.

**Оцінка.** Власник: L. Автор: L, 3 PR (ядро й команда в detent; Action, документація й випуск; перехід
warsaw-beer-bot) і кроки поза репозиторієм (публікація, порівняння за твоїм ключем). Розбивка: ядро 55%,
Action і документація 15%, перехід із порівнянням 30%. Дешевший варіант: лишити warsaw-beer-bot на власній
копії; економить близько 30%, але суперечить вимозі 2 і лишає пакет без жодного справжнього користувача.

**Питання до власника.** Немає. Обсяг рев'ю, витрати на порівняння й те, що detent поки без рев'ю, — мої
пропозиції вище в «Що зміниться для тебе»; перевір їх першими.

## Тіло

Типові моделі в пакеті: `gpt-5.6-sol` і `gpt-5.5`, бо саме на них зміряні цифри із засновку 1. Кількість прогонів
порівняння: детермінізму немає, тож одного мало, а прогін коштує від $0,11 до кількох десятих (П-4).

`package.json` у теці самої Action.

### Команда

```
detent pr-review               # у GitHub Actions: контекст береться з події
detent pr-review --replay <n> [--head <sha>] [--base <sha>]  # локально: прогін для PR <n> без публікації
```

У CI команда читає `GITHUB_EVENT_PATH`, `GITHUB_REPOSITORY`, `GITHUB_TOKEN`, `OPENAI_API_KEY`. Подія не
`pull_request` або немає потрібних змінних — код 2. `--replay` бере дані PR через `gh` і вміст файлів через
`git show` на голові PR, як нинішній `replay.ts`, зокрема на минулій голові через `--head`.

`--replay` відрізняється від запуску в CI в двох місцях, бо його запускає власник ключа на своїй машині, а не
чужий PR:
- конфіг і промпти читаються з робочого дерева, а не з бази, інакше настройки неможливо виміряти до злиття;
- діють змінні `AI_REVIEW_MODEL`, `AI_REVIEW_VERIFY_MODEL`, `OPENAI_API_ENDPOINT`, якими протокол вимірювань
  warsaw-beer-bot перебирає кандидатів. У CI вони ігноруються, щоб ендпойнт ішов лише з бази.

`--replay` друкує підсумок знахідок і рядок витрат у тому ж форматі, що й CI.

| Код | Значення |
|---|---|
| 0 | рев'ю опубліковане, пропущене без файлів у межах або пропущене в PR із форка |
| 2 | помилка використання чи конфігу, зокрема зламаний `detent.json` на базовій гілці |
| 5 | рев'ю не завершилось; у PR іде коментар про збій, який оновлюється, а не множиться |

Без ключа: PR із форка (`head.repo` не збігається з `base.repo`) — повідомлення й код 0; інакше код 5.

### Конфіг

Новий ключ `prReview` у `detent.json`; усі поля необов'язкові.

| Поле | Типове значення | Значення |
|---|---|---|
| `include` | `["**"]` | що рецензувати |
| `ignore` | `["**/*.md", "docs/**", "package-lock.json"]` | що не рецензувати; поза `include` файл теж не рецензується, і рев'ю їх рахує окремо |
| `bodyExclude` | `["**/*.test.*", "tests/**"]` | чиє тіло не йде в контекст; diff іде, знахідки дозволені |
| `bodyInclude` | `[]` | винятки з `bodyExclude`; для `scripts/ops/test_run.py` у warsaw-beer-bot, де це зараз записано в коді |
| `findModel` | `gpt-5.6-sol` | модель пошуку |
| `verifyModel` | `gpt-5.5` | модель перевірки |
| `endpoint` | `https://api.openai.com/v1` | сумісний з OpenAI ендпойнт; бюджет контексту й інші константи лишаються в коді |

Конфіг читається через `git show origin/<база>:detent.json`, промпти — через `git show
origin/<база>:.detent/prompts/pr-review-find.md`, а якщо їх немає, то з пакета. Немає файлу на базі — типові
значення. Невідомий ключ у `prReview` — код 2: помилка в цьому полі інакше мовчки дала б неправильний обсяг
рев'ю. `reviewContext` підставляється в типові промпти як `{{reviewContext}}`; перевизначений промпт може
його не використовувати. Заповнює їх наявний `renderPrompt`.

### Action

Вхід: `api-key` (обов'язковий), `github-token` (типово `github.token`). Кроки:

1. `actions/checkout@v7`: голова PR, `fetch-depth: 0`, `persist-credentials: false`.
2. `actions/setup-node@v7`, Node 24.
3. Прочитати версію з `${{ github.action_path }}/package.json`; виконати `npm i --prefix
   "$RUNNER_TEMP/detent" --ignore-scripts @ysilvestrov/detent@<версія>`. У цьому кроці секретів немає.
4. Запустити `node "$RUNNER_TEMP/detent/node_modules/@ysilvestrov/detent/dist/cli.js" pr-review`, ключ лише в
   env цього кроку.

Код PR не виконується: `npm ci` проєкту не потрібен, на відміну від нинішнього workflow. Модель викликається
без інструментів, лише текст і JSON-схема.

Workflow проєкту (`examples/pr-review.workflow.yml`): `pull_request` типів `opened, reopened, synchronize`;
`permissions: contents: read, pull-requests: write`; `concurrency` за номером PR зі скасуванням; умова
`user.login != 'dependabot[bot]'`, бо Dependabot не отримує секретів і дав би червоний статус; `uses:
ysilvestrov/detent@<SHA> # v0.4.0`. SHA, бо ця дія отримує ключ, так само закріплено `claude-code-action` у
warsaw-beer-bot.

### Що переноситься, що змінюється

Без змін: логіка етапів, фільтр цитат, правила carry/recheck/close, ліміти, маркери `<!-- ai-pr-review -->`,
`<!-- ai-pr-review-state ...`, `<!-- ai-pr-review-failure -->` і `v: 1` стану, чиї наявні поля лишаються тими самими.

Змінюється:
- У стан додається необов'язкове поле `scope`: хеш чинних `prReview`, `reviewContext` і текстів обох промптів.
  Інакше зміна настройок не вплинула б на вже рецензований PR: новий файл у межах лишився б непереглянутим у режимі
  `incremental`, а повторний запуск тієї самої голови просто републікував би старе рев'ю. `scope` не збігся — режим
  `full`, знахідки далі звіряються за наявними правилами. Поля немає (стан від старої версії) — вважається, що збігся:
  перехід warsaw-beer-bot переносить настройки дослівно, тож платити за повторні рев'ю відкритих PR нема за що.
- CommonJS → ESM (`.js` в імпортах, без `require.main`).
- `zod` → власні перевірки з тими самими відмовами. Перенесені тести мають пройти без зміни очікувань, окрім
  тексту повідомлень про помилки.
- Переліки файлів і `readInstructions` приходять із конфігу, а не з констант.
- `User-Agent` без назви проєкту.
- Текст про збій: «required AI review» → без «required», бо перевірка не обов'язкова (П-3).
- Промпти: загальні в пакеті, специфіка warsaw-beer-bot лишається в нього як перевизначення.

Спека першого релізу передбачала, що HTTP-транспорт ляже поруч із наявним протоколом. Це не підтвердилось:
`CROSS-REVIEW-RESULT` і маркери `cross-review` тут не потрібні, бо є JSON-схема й власний стан. Спільні лише
`renderPrompt` і конфіг, тому `src/review/` не змінюється.

### Вимірювання

`--replay` замінює `scripts/ai-review/replay.ts`. Корпус для `verify` (`verify-corpus*`) прив'язаний до коду
warsaw-beer-bot, тож лишається там і бере `verifyAll`, `costUsd`, `addUsage`, `EMPTY_USAGE`,
`DEFAULT_MAX_COMPLETION_TOKENS` з `@ysilvestrov/detent/pr-review`. Цей імпорт задокументовано як нестабільний:
warsaw-beer-bot закріплює точну версію (уже так: `"@ysilvestrov/detent": "0.3.0"`). Додавання `exports`
обмежує прямий імпорт інших шляхів пакета; `bin` воно не зачіпає, але `smoke` це підтвердить.

### Перехід warsaw-beer-bot

Один PR після публікації `0.4.0`:
1. `prReview` у `detent.json`: його `INCLUDE_PATTERNS`, `IGNORE_PATTERNS`, `BODY_EXCLUDE_PATTERNS`, виняток
   для `test_run.py`.
2. `.github/ai-review/AGENTS.md` і `VERIFY.md` переїжджають у `.detent/prompts/pr-review-find.md` і
   `pr-review-verify.md` дослівно.
3. `codex-review.yml` замінюється на workflow з прикладу, ім'я перевірки лишається `review`.
4. `scripts/ai-pr-review.ts`, його тести й перенесені модулі видаляються через `git rm` із буквальними шляхами.
   Інструменти корпусу перемикаються на новий імпорт; згадки в `AGENTS.md`, `CLAUDE.md`, `spec.md` і
   `docs/ai-review-model-evaluation.md` оновлюються.

Сам цей PR отримає рев'ю за типовими настройками, бо база їх ще не має. Це разово. PR, відкриті на момент
переходу, зберігають стан завдяки незмінному формату.

### Приймання

**detent.** Перенесені тести зелені на gate. Додатково: відмова з кодом 5 без ключа в PR не з форка і код 0 із
форка; PR із зміненим `prReview` чи промптом використовує версію бази (реальний git-репозиторій у тесті);
невідомий ключ у `prReview` дає код 2; стан із живого PR (зафіксований зразок) читається без втрат; змінений
`scope` дає режим `full`, а стан без `scope` — звичайне рішення за головою.

**Порівняння в сесії переходу** за протоколом `docs/ai-review-model-evaluation.md` у warsaw-beer-bot: нинішній
код і `--replay` на 5 головах, які бачило живе рев'ю (видно в `ai-pr-review-state`), по 3 прогони, з однаковими
моделями й промптами, базлайн міряється в тій самій сесії. Новий код запускається з гілки переходу, де вже є
настройки. Нинішній `replay.ts` витрат не друкує, тож для базлайну до нього додається лише друк витрат із уже
наявних `usage`; ця правка живе в сесії вимірювань і не зливається. Рівні: покриття відомих дефектів на пробі покриття
не менше; знахідок за прогін і об'єднаних у межах розкиду базлайну; витрати на прогін у межах розкиду. Якщо ні,
перехід не йде, а причина шукається як дефект перенесення. Це порівняння кількостей і відомих дефектів: чи правильні
решта знахідок, воно не доводить. Знахідки нової версії, яких немає в базлайні, перевіряються лише вибірково,
читанням.

**Перший живий запуск** на PR переходу: статус зелений, рев'ю опубліковане, знімає засновок 10. Перший push
після нього йде в режимі `incremental`.

### Проби

**П-1. Код warsaw-beer-bot** (`origin/main` 12c7346e; файли рев'ю збігаються з локальною копією). Без тестів і
інструментів вимірювань близько 2300 рядків разом із `context.ts`; тести близько 3100. Сторонні імпорти лише
`zod` (`find.ts`, `state.ts`, `verify.ts`). Назва проєкту в коді лише в `User-Agent`. Специфіка: `INCLUDE_PATTERNS`,
`IGNORE_PATTERNS`, `BODY_EXCLUDE_PATTERNS`, `.github/ai-review/*.md`.

**П-2. Запуск пакета.** У репозиторії detent `npx -y @ysilvestrov/detent@0.3.0 --version` дає `'detent' is not
recognized`, тобто версія не обходить відому проблему. `npm i --prefix <тека> --ignore-scripts
@ysilvestrov/detent@0.3.0`, далі `node <тека>/node_modules/@ysilvestrov/detent/dist/cli.js --version` з репозиторію
detent дає `0.3.0`, код 0.

**П-3. Налаштування warsaw-beer-bot.** `branches/main/protection/required_status_checks`: `["ci"]`, тобто рев'ю
не обов'язкове, хоча текст збою каже «required». Останні 100 запусків: 75 success, 23 skipped, 2
action_required, жодного failure. Із 200 останніх PR один із форка. Секрети: `CLAUDE_CODE_OAUTH_TOKEN`,
`OPENAI_API_KEY`.

**П-4. Живі запуски.** PR #939, журнал запуску 41312888775: `AI review cost: ... this run $0.11 · PR total $1.24`,
режим `incremental`, `Context budget: 1 file(s) sent as diff only`. У тілі рев'ю цього PR є `ai-pr-review-state`.
Запуск 41459141081 на PR без файлів у межах: `skipped`, без викликів API.

**П-5. detent.** Секретів у репозиторії немає (`gh secret list` порожній). `dist/` у `.gitignore`, `exports` у
`package.json` немає, у npm останнє `0.3.0`.

## Заявка → доказ

| Заявка | Де записано | Що доводить | Сила |
|---|---|---|---|
| Знахідку підтверджено | рев'ю в PR | цитата знайдена у файлі механічно (`gate`), вердикт `confirmed` другої моделі | середня: другий етап теж модель; людина вирішує |
| Знахідку закрито | список закритих у рев'ю | файла немає або повторна перевірка її спростувала | середня; за помилки API знахідка лишається відкритою, а не закривається |
| Витрати за прогін | рядок витрат, стан | токени з відповіді API × таблиця цін | сильна для токенів, слабка для доларів: таблиця ручна, невідома модель показує лише токени |
| PR перевірено на цій голові | поле `head` стану, статус | запуск на цьому SHA | сильна; нічого не каже про файли поза `include` (рев'ю їх рахує) |
| Версія з пакета знаходить відомі дефекти й дає той самий обсяг і ціну, що стара | опис PR переходу | порівняння з розділу «Приймання» | середня: 5 голів одного проєкту. Заявки «не гірша за якістю» немає: правильність інших знахідок не міряється |
| Цифри цінності рев'ю | ця спека, засновок 1 | дані власника, не переміряні | слабка для інших проєктів, тому в README як дані одного проєкту, а не обіцянка |
