# Рецензент `agy`: доступ до diff і відмова без звіту

Дата: 2026-11-02
Статус: чернетка
Spec-review: —

## Для власника

**Мета.** `agy` стає робочим рецензентом в обох режимах cross-review. Зараз рев'ю гілки через нього
не може вдатися взагалі, а рев'ю спеки падає без звіту. Через це ланцюжок `codex → agy` фактично має
одного рецензента. Закриває issue #6.

**Що зміниться для тебе.**
- Коли `codex` недоступний або впав, рев'ю зазвичай зробить `agy`, а не маркер `failed (…)`.
- Твоїх дій не потрібно. Нічого незворотного: зміна в одному адаптері, ставиться наступним релізом.
- Без тебе відбувається те саме, що й раніше: канарка, потім рев'ю. Нового автоматизму немає.
- Рецензент `agy` отримує право читати теку свого запуску, а не лише snapshot. Запис і далі
  заборонено.

**На чому стоїть рішення.**
1. Читання поза робочою текою headless-режим відхиляє автоматично. Рев'ю diff читає `branch.diff`
   поза snapshot, тому падає завжди, у Windows і WSL. Issue #6 цього не бачив. `[проба]` (П-2, П-6)
2. Після будь-якої такої відмови модель завершує хід порожньою відповіддю: exit 0, звіту немає. Це
   стосується і shell, і читання. Спеку з issue зламав `Get-ChildItem`, а не `git`. `[проба]` (П-1)
3. `--add-dir` лікує читання diff, а deny-правило в доданій теці далі блокує запис. `[проба]` (П-2, П-5)
4. `--add-dir` із загальною преамбулою («без shell, лише `read_file`») мало: 2 рев'ю з 4 падали, бо
   модель читала вище за snapshot. `[проба]` (П-3)
5. Преамбула з абсолютним шляхом до snapshot прибрала відмови: 8 звітів із 8. Це зменшує ймовірність
   збою, а не виключає його: модель може не послухатись. `[проба]` (П-4)
6. Read-only не можна послаблювати. `--dangerously-skip-permissions` заборонено. `[вимога власника]`
7. Читання diff раніше не падало в пробах лише тому, що вони були в системному temp: схоже, він не
   потребує дозволу. Механізм не з'ясовано, але на рішення це не впливає. `[виведення]`

**Ключові рішення.**
1. `--add-dir <runDir>` у команді й рев'ю, і канарки, щоб канарка перевіряла ту саму конфігурацію.
   Відкинуто: `--add-dir` кореня репозиторію (рецензент читав би робоче дерево замість snapshot);
   класти diff усередину snapshot (snapshot перестає бути точним знімком `sha` і це зачепило б усіх
   рецензентів); diff у промпті (ліміт довжини командного рядка Windows).
2. Преамбула живе в адаптері `agy` і лише в команді рев'ю, а не в `prompts/review-*.md`. Промпти
   спільні, а в `codex` shell для читання є, тож там ці слова були б неправдою. Так само вона діє для
   проєктів із власним `.detent/prompts/`.
3. Shell лишається закритим. Відкинуто: вузьке allow на `command(...)` (запис через `echo > file`;
   перелік команд невідомий наперед, бо модель обирає їх сама).
4. Канарка не розширюється на shell: allow немає, тож цей шлях не відкривається. Відмову в shell уже
   показала П-1. Issue #6 вимагав розширення лише на випадок allow.
5. Розглянуто стандартне: дозвіл `read_file(*)` через `permissions.allow` — відкинуто, бо це читання
   всього диска з правами користувача. `--add-dir` дає лише теку запуску.

**Що стане гірше.**
- Рецензент читає ще й теку запуску: свій diff, а також лог і звіт свого запуску. Сторонніх даних там
  немає.
- Гарантії немає: якщо модель усе ж вийде за межі, буде той самий збій без звіту. Ланцюжок
  перейде далі, а причина лишиться в логу, не в маркері.
- Промпт для `agy` довший на чотири речення й залежить від назви `read_file` у цій версії CLI (1.4.12).
- Перевірено на коротких diff і спеці цього репозиторію, у невеликій кількості запусків. Рев'ю в
  проєкті зі встановленими скілами не проганялося.

**Оцінка.** Власник: S. Автор: S (один PR, 2–3 задачі). Розбивка: адаптер і тести 60%, спека й README
25%, проби 15%. Дешевший варіант: лише `--add-dir`, без преамбули; лагодить читання diff, але не
збої моделі. Рев'ю спеки без преамбули падало 2 рази з 2 (П-1), а рев'ю diff падало 2 рази з 4 навіть
із загальною преамбулою (П-3). Сам цей варіант окремо не мірявся.

**Питання до власника.** Немає.

## Тіло

### Механізм

```
промпт називає файл → модель тягнеться до дії, що потребує дозволу
  → headless відхиляє її автоматично → модель завершує хід порожньою відповіддю
  → exit 0, stdout порожній, stderr: jetski: no output produced — a tool required the "<x>" permission…
  → classifyRun: output does not end with a CROSS-REVIEW-RESULT line
```

`<x>` буває `command` (issue #6) і `read_file` (нове). `classifyRun` це вже обробляє правильно, а
тест на `command` уже є в `cli-runner.test.ts`; додається такий самий на `read_file`.

### Зміни

`src/review/adapters.ts`:
- `agyArgs` отримує `runDir` і додає `'--add-dir', runDir` перед `-p`: усі прапорці стоять до `-p` (П-А3
  зі спеки релізу 1). Так зміна діє і на `command`, і на `canary`.
- `command` дописує перед промптом преамбулу (текст нижче) зі шляхом `runArtifacts(p.runDir).snapshot`.
  `canary` преамбули не отримує: її завдання якраз дійти до `write_file`.

```
You have no shell in this session: a shell command is denied. The repository is <snapshot>, your
current directory. Read files with read_file and absolute paths only, inside that folder or the diff
file named below if there is one. Any other read is denied too, and a denied action ends your run
with no report. If a file named below does not exist, say so in one line and go on; never stop
without the report.
```

Преамбула не називає `view_file`, `list_dir`, `find_by_name`, `grep_search`. Вони є в полі `tools`
події `init`, але модель їх не бачить і не викликає (П-7). Не просить і відносних шляхів: `read_file`
їх не приймає (П-4).

`README.md`: рядок `agy` у таблиці команд і абзац у «`agy`: the deny rule and the canary». Команда в
таблиці спеки релізу 1 лишається як є: то історичний документ.

### Тести

- `adapters.test.ts`: точні `args` команди рев'ю (зі snapshot у преамбулі й `--add-dir`) і канарки
  (з `--add-dir`, без преамбули).
- `cli-runner.test.ts`: exit 0, порожній stdout, `jetski…"read_file" permission` дає той самий збій,
  що й для `command`.

Живий виклик `agy` у тести не входить (потрібні модель і вхід). Перевірка перед PR: `node dist/cli.js
cross-review --author claude --reviewer agy` в обох режимах.

### Проби

Усі: `agy` 1.4.12, `gemini-4-argon`, `--settings '{"permissions":{"deny":["write_file(*)"]}}'
--sandbox`, cwd — snapshot, якщо не сказано іншого. У таблицях «звіт» означає останній рядок
`CROSS-REVIEW-RESULT`.

**П-1. Відтворення issue (Windows, `--output-format stream-json`, спека, без преамбули).**

```
2 read_file  …\.agents\skills\detent-design-spec\spec-format.md → file does not exist
3 read_file  …\.claude\skills\detent-design-spec\spec-format.md → file does not exist
5 run_command Get-ChildItem -Path . -Recurse -Filter "spec-format.md" … → user denied permission
result: status SUCCESS, response "", denied_actions [{"action":"command"}]
```

Разом із запуском з issue — 2 збої з 2.

**П-2. Читання diff (Windows, `<repo>/tmp/probe5/<run>/{diff.patch,snapshot}`).**

| Варіант | Запусків | Звітів | Відмова |
|---|---|---|---|
| без `--add-dir` | 3 | 0 | `read_file` на `diff.patch` |
| справжній CLI, `tmp/` репозиторію, без `--add-dir` | 1 | 0 | `jetski…"read_file" permission` |
| контроль: той самий diff у системному temp, без `--add-dir` | 8 | 8 | немає |

**П-3. `--add-dir` і перша преамбула («Read files with read_file only»).** 4 diff: 2 звіти, 2 збої з
відмовою на `C:\Projects\detent\spec.md` і `C:\Projects\detent\CLAUDE.md`, тобто вище за snapshot.
Спека без `--add-dir`: 2 звіти з 2.

**П-4. `--add-dir` і преамбули зі словами про поточну теку.**

| Формулювання | Запусків | Звітів | `denied_actions` | Примітка |
|---|---|---|---|---|
| «поточна тека, відносні шляхи» | 6 diff, 2 спеки | 8 | порожньо | відносні шляхи відхилено: `must be an absolute path` |
| остаточне (вище) | 6 diff, 2 спеки | 8 | порожньо | лише `file does not exist` на файлах, яких немає |

**П-5. Канарка і запис із `--add-dir`.** Канарка з `--add-dir` на ту саму теку: файла немає, exit 0,
`deny rule` у виводі. Без `--add-dir`, у тимчасовому git-репо: `replace_file_content` і
`write_to_file` → `Permission denied for write_file(…). Matches user-configured deny rule.`, файли без
змін; `sed_file` і `notebook_edit` модель називає недоступними.

**П-6. WSL (`~/detent-probe-wsl`, короткий промпт «прочитай файл поза cwd»).**

```
без --add-dir: jetski: no output produced — a tool required the "read_file" permission…
з --add-dir:   DIFF-MARKER-71
```

Повне рев'ю у WSL не проганялося.

**П-7. Назви інструментів.** У подіях усіх проб викликається лише `read_file`. Три прогони `agy` по
чернетці з `view_file`, `list_dir` тощо незалежно повідомили, що цих інструментів немає.

### Що свідомо не робимо

- Причина `jetski…` у маркері: корисно, але окрема зміна, і спека релізу 1 прямо описує нинішню
  поведінку. Причина лишається в `reviewer.log`.
- Повтор запуску після такої відмови.
- Покриття MCP-інструментів deny-правилом: обмеження вже описане в README.
- Чи може глобальний `settings.json` користувача з allow на `command` відкрити shell у цій сесії. Це
  існує й сьогодні, ця зміна на нього не впливає, тому не перевіряється тут.

## Заявка → доказ

| Заявка | Де записано | Що доводить | Сила |
|---|---|---|---|
| Рецензент `agy` не міг змінити код | маркер | канарка цього ж запуску в тій самій конфігурації, з `--add-dir` (П-5) | сильна для `write_file`/`edit_file`; MCP не покрито |
| Зроблено рев'ю `agy/<model> @ <sha>` | маркер | рядок `CROSS-REVIEW-RESULT` наприкінці stdout | як і раніше |

Що рецензент справді прочитав diff, маркер не заявляє: цього не доводить жоден рецензент.
