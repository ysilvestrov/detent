# CI gate на GitHub і smoke-перевірка пакета

Дата: 2026-11-02
Статус: чернетка

## Для власника

**Мета.** Кожен PR і кожен push у `main` автоматично перевіряє збірку, тести й те, що запакований
`detent` реально встановлюється і працює на Linux та Windows. Зламаний пакет видно до злиття, а не
після `npm publish`.

**Що зміниться для тебе.**
- На PR з'являються три статуси. Без тебе нічого не публікується і нічого не зливається: CI лише
  читає репозиторій.
- Червоний статус поки не блокує злиття. Зробити перевірку обов'язковою можна в налаштуваннях гілки
  після першого зеленого запуску; це твоє рішення і твоя дія, поза цією зміною.
- З'являється команда `npm run smoke`, яку можна запустити локально. У крок 3 випуску вона додається
  після `npm run gate`.
- Нічого незворотного: workflow і скрипт видаляються одним revert.

**На чому стоїть рішення.**
1. CI перевіряє збірку й базову роботу скриптів, публікація йде окремо. `[вимога власника]`
2. Перевірка команд живе в окремому скрипті, а не в кроках YAML чи в vitest. `[вимога власника]`
3. Випуск лишається ручним, з 2FA (спека npm-пакета). `[вимога власника]`
4. Жоден наявний тест не запускає зібраний `dist/cli.js` і не перевіряє склад архіву. `[проба]` (П-5)
5. Запакований `detent` встановлюється, а всі заплановані команди дають очікувані коди виходу на
   Windows і в WSL. `[проба]` (П-1, П-2)
6. `npm run gate` проходить з чистого клону в WSL з порожнім `HOME` і без git-ідентичності. `[проба]` (П-2)
7. Збірка й запуск працюють на Node 20, мінімумі з `engines`. `[проба]` (П-3)
8. Раннер GitHub поводиться так само, як WSL. Це не перевірено: WSL не є раннером, і голий Linux досі
   не запускав цей пакет. Перший запуск CI це покаже. `[виведення]`
9. Для публічного репозиторію хвилини Actions безкоштовні, а Actions увімкнено. `[проба]` (П-4) для
   «увімкнено», `[виведення]` для «безкоштовні».

**Ключові рішення.**
1. Smoke перевіряє встановлений архів (`npm pack`, `npm install`), а не `dist/` у репозиторії. Лише так
   видно зламаний `bin` чи неповний `files`. Відкинуто: виклики `node dist/cli.js` (цього власник не
   обрав, і пакування лишилося б неперевіреним).
2. `npm run smoke` не входить у `npm run gate`. Gate запускається після кожної задачі, а smoke
   пакує і ставить пакет. Відкинуто: один спільний gate. Ціна: локально smoke можна забути, тому
   його завжди запускає CI.
3. Три конфігурації замість повної матриці: Ubuntu + Node 24 і Windows + Node 26 з повним gate і smoke,
   Ubuntu + Node 20 лише зі smoke. Перші дві повторюють перевірені машини власника (WSL і Windows).
   На Node 20 vitest не обіцяє підтримки (`engines` у нього від 22.12), тож там перевіряємо те, що
   обіцяємо користувачам: пакет збирається і працює. Відкинуто: повна матриця 2×3 (шість запусків на
   кожен PR без нових знань).
4. Справжні рецензенти (`codex`, `claude`, `agy`) у CI не запускаються: це ключі, гроші й нестабільність.
   `cross-review` у smoke перевіряється лише на відмову. Тому `--author codex` і `agy` лишаються
   неперевіреними.
5. Розглянуто стандартне: вимога обов'язкового статусу через захист гілки в цій зміні — відкинуто, бо
   це налаштування репозиторію, а перший запуск може бути червоним через засновок 8.

**Що стане гірше.**
- Кожен PR чекає на три запуски, Windows повільніший за Linux. Точний час покаже перший запуск.
- Перший запуск може виявити реальні помилки на голому Linux, і їх доведеться лагодити в цьому ж PR.
- Новий файл для підтримки: smoke перевіряє точні коди виходу й шляхи, тож зміна в CLI може вимагати
  правки в ньому.
- Версії дій закріплені мажорними тегами, а не SHA: новий випуск тієї самої мажорної версії приходить
  без рев'ю. Ризик обмежений: у workflow немає секретів і прав на запис.
- Зелений статус нічого не каже про рецензентів і про справжнє встановлення з реєстру npm.

**Оцінка.** Власник: S. Автор: S, один PR, план до 4 задач. Розбивка: smoke-скрипт 60%, workflow 20%,
перевірка, що smoke справді ловить поломки, і документація 20%. Дешевший варіант: кроки в YAML
без пакування; втрачає перевірку `bin` і `files`, власник його не обрав.

**Питання до власника.** Немає.

## Тіло

### Файли

| Файл | Зміна |
|---|---|
| `.github/workflows/ci.yml` | новий |
| `scripts/smoke.mjs` | новий, лише вбудовані модулі Node |
| `package.json` | `"smoke": "node scripts/smoke.mjs"`; `files` не змінюється, тож скрипт не потрапляє в пакет |
| `README.md` | CI і `npm run smoke` у «Working on detent itself», smoke у кроці 3 випуску |

### Workflow

- Запуск: `pull_request` і `push` у `main`. Не `pull_request_target`: код із PR не отримує прав.
- `permissions: contents: read`, `persist-credentials: false`, `timeout-minutes: 15`, `fail-fast: false`,
  щоб падіння на одній ОС не ховало результат іншої.
- Кроки: `actions/checkout@v7`, `actions/setup-node@v7` (із кешем npm), `npm ci`, `npm run gate` там,
  де конфігурація його передбачає, `npm run smoke`.
- Без публікації, без секретів.

### Smoke

Скрипт `scripts/smoke.mjs` (`.mjs`, бо Node 20 не запускає TypeScript; `tsconfig` включає лише `src`):

1. Створює тимчасову теку в `os.tmpdir()` і видаляє її наприкінці, навіть після падіння.
2. Виконує `npm pack --pack-destination <tmp>`. `prepack` при цьому збирає `dist/`.
3. Створює там теку-споживача з `{"private":true}`, виконує `npm install <tgz>` і `git init`.
4. Викликає лише `npx --no-install detent …` у теці-споживачі, тож перевіряється саме `bin` із пакета.
   На Windows запуск іде через shell, бо `npx` там є `.cmd`. Аргументи фіксовані, зовнішніх даних немає.
5. Прибирає зі середовища дочірніх процесів `DETENT_AUTHOR` і `CROSS_REVIEW_ACTIVE`, інакше результат
   залежав би від того, чи запущено скрипт агентом.

| Перевірка | Очікування |
|---|---|
| `--version` | код 0, stdout дорівнює `version` із `package.json` |
| `nope` | код 2, stderr містить `unknown command` |
| `cross-review` без `--author` | код 2, stderr містить `--author` |
| `install --claude --agents --dry-run --superpowers no` | код 0, stdout містить `nothing written`, `CLAUDE.md` не створено |
| `install --claude --agents --superpowers no` | код 0; є `CLAUDE.md`, `AGENTS.md`, `detent.json`, `.detent/manifest.json`, `.claude/skills/detent-dev-cycle/SKILL.md`, `.agents/skills/detent-dev-cycle/SKILL.md` |
| той самий `install` удруге | код 0, жодного рядка `create` чи `update` |
| `prompts/review-diff.md`, `prompts/review-spec.md` у встановленому пакеті | файли є: `cross-review` без них не працює, а до них smoke інакше не дістається |

`--superpowers no` прибирає залежність результату від `HOME` машини. `install` читає `HOME`, але не
пише туди (`src/commands/install.ts`). На першому провалі скрипт друкує команду, код виходу й вивід і
завершується з кодом 1.

### Приймання

Smoke має бути червоним на зламаному пакеті, а не лише зеленим на справному. Перед PR перевірити
локально три поломки, кожну окремо, і потім скасувати: прибрати `bin` із `package.json`; прибрати
`skills` із `files`; змінити код виходу для невідомої команди в `src/cli.ts`. У кожному випадку
`npm run smoke` завершується не нулем.

Перший зелений запуск усіх трьох конфігурацій на GitHub є умовою завершення зміни. Він же знімає
засновок 8.

### Проби

**П-1. Windows, Node 26.12.1, npm 11.20.0.** `npm pack` у тимчасову теку (архів 38 432 байти), `npm install`
архіву: код 0. `npx --no-install detent --version`: `0.3.0`, код 0. `detent nope` і `detent` без аргументів:
код 2. `cross-review` без `--author`: код 2, `--author claude|codex|agy (or DETENT_AUTHOR) is required`.
`install --dry-run`: код 0, `nothing written`, `git status` порожній. Справжній `install`: код 0, 15 файлів
`create`. Повторний: код 0, усі показані рядки `unchanged`.

**П-2. WSL Ubuntu, Node 24.22.2, npm 11.19.1, чистий клон `0966d2b`, порожній `HOME`, `GIT_CONFIG_NOSYSTEM=1`,
`git config --global --list` порожній.** `npm ci` пройшов. `npm run gate`: код 0, 529 тестів. Далі ті самі
команди, що в П-1, зі встановленого архіву: `0.3.0`; код 2; код 2; dry-run без змін; справжній `install`
створив `.agents/ .claude/ .detent/ .gitignore AGENTS.md CLAUDE.md detent.json`. `node_modules/.bin/detent`
є символічним посиланням на `dist/cli.js`.

**П-3. WSL, Node 20.20.2 (тимчасова копія з пакета `node@20`).** `npm ci` пройшов із попередженням
`EBADENGINE` про `vitest@5.0.5`, який вимагає `^22.12.0 || ^24.0.0 || >=26.0.0`. `npm run build`: код 0.
`node dist/cli.js --version`: `0.3.0`. `npm test` теж дав код 0, але на це не спираємось: vitest такої
підтримки не обіцяє.

**П-4. Налаштування GitHub.** `actions/permissions`: `enabled: true`, `allowed_actions: all`,
`sha_pinning_required: false`. Workflow у репозиторії: 0. Захисту `main` немає (HTTP 404). Останні версії:
`actions/checkout` v7.0.1, `actions/setup-node` v7.1.0.

**П-5. Наявні тести.** Пошук `dist/cli`, `npm pack` у `src/**/*.test.ts`: нічого. `spawnSync` у тестах
запускає лише `git`. Команди тести викликають як функції.

## Заявка → доказ

| Заявка | Де записано | Що доводить | Сила |
|---|---|---|---|
| Пакет збирається, тести проходять | статус GitHub | виконаний `npm run gate` на цьому коміті | сильна |
| Встановлений пакет працює | статус GitHub | smoke зі встановленого архіву і поломки з «Приймання» | сильна для перелічених команд, нічого не каже про решту |
| Пакет працює на мінімальному Node | статус конфігурації Node 20 | smoke на Node 20; лише версія з раннера, не кожна 20.x | середня |
